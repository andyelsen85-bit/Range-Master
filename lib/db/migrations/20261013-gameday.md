# Daily reports, club inventory and daily configuration backups

Apply `20261013-gameday.sql` to the deployment's existing PostgreSQL database
before releasing the corresponding API and portal. It is transactional and
can be rerun. It has been applied to the development database; publishing code
does not apply it to a separately managed production database.

The migration backfills Luxembourg calendar dates, removes redundant
unprotected same-day snapshots, and installs the strict daily unique index.
It deliberately aborts rather than silently deleting a protected snapshot
when conflicting historical restore approvals cannot satisfy that index.
Review/revoke obsolete approvals before retrying such a migration.

Daily mail and the public `/live` page are initially disabled. Configure SMTP
in the existing Mail settings, add active report recipients, then use
**Testmail senden** before enabling automatic reports. Public visibility and
the FULL/INITIAL name setting are independent administrator choices.

The API process runs the 30-second scheduler. Delivery claims are shared in
PostgreSQL, failed deliveries retry at 15-minute intervals for six hours, and
an interrupted delivery with unknown SMTP acceptance is marked for manual
review rather than automatically risking a duplicate message.

Deploy the matching terminal firmware to use the new inventory screen,
immutable inventory outbox, Maître roster flags and one daily automatic
backup. Existing configuration encryption and restore approval binding remain
unchanged. Run the complete ESP32-P4 ESP-IDF build and verify power-cycle
recovery on the actual terminals before replacing installed firmware.
